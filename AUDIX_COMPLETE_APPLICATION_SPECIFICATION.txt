1. EXECUTIVE OVERVIEW & PRODUCT IDENTITY
====================================================================================================
Audix (developed under the internal project name Echo Desktop / echo-nightly) is an enterprise-grade,
ultra-high-fidelity desktop audio player, music streamer, and media manager engineered with Kotlin
Multiplatform and Jetpack Compose Desktop.

1.1 Core Mission & Design Principles:
  - Universal Catalog Aggregation: Seamlessly merges music streaming catalogs across YouTube Music,
    JioSaavn, Spotify, SoundCloud, Radio Browser, and local filesystem libraries into a single
    monolithic listening environment.
  - Zero-Latency Playback: Powered by native LibVLC 3.x bindings with low-jitter HTTP stream caching,
    adaptive Opus/AAC audio extraction, and instantaneous buffer pre-warming.
  - Strict Monochrome Aesthetics: Features a senior-developer minimalist monochromatic palette
    (deep obsidian black #070913, liquid glass trans-opacity layers, and crisp typography) with
    no oversaturated distraction colors.
  - Portable Zero-Installer Distribution: Runs completely self-contained with embedded VLC native
    binaries, runtime dependencies, and isolated ClassLoader extensions without requiring system
    administrator privileges or registry writes.
  - Millisecond Synchronized Lyrics: Real-time karaoke timecode alignment via crowdsourced LRCLIB,
    Musixmatch, and Genius engines.
  - Dynamic Visual Experience: Features an ambient 3D album mosaic screensaver, Apple iOS lockscreen
    miniplayer aesthetics, and a cosmic gravitational lensing vortex clock.

2. ARCHITECTURAL BLUEPRINT & TECHNOLOGY STACK
====================================================================================================
Audix is architected as a layered reactive system following Unidirectional Data Flow (UDF) and
Clean Architecture principles.

2.1 Technology Stack Matrix:
  - Programming Language: Kotlin 2.2.10 (Targeting JVM 21 bytecode)
  - UI Framework: Compose Multiplatform for Desktop 1.7.3 (Skia rendering engine / AWT host)
  - Audio Backend: VideoLAN LibVLC 3.0.x via vlcj 4.8.x and Java Native Access (JNA 5.14.0)
  - Dependency Injection: Koin Multiplatform 4.0.0 (Global singleton context and screen injection)
  - Reactive Asynchronous Flows: Kotlinx Coroutines 1.9.0 (StateFlow, SharedFlow, Dispatchers.IO/Main)
  - Serialization: Kotlinx Serialization JSON 1.7.3 (Type-safe domain serialization)
  - HTTP Network Layer: Square OkHttp 4.12.0 / 5.0 with custom security, retry, and SSRF interceptors
  - Image Loading Pipeline: Coil3 Compose 3.0.0 with dual memory-caching and fallback resource loaders
  - Isolated Plugin System: URLClassLoader sandbox per extension JAR with dynamic manifest discovery
  - Desktop Interoperability: Java Desktop AWT API, Windows Explorer ProcessBuilder integrations

2.2 Architecture Layers:
  [UI Layer]: Compose Desktop Composables (HomeScreen, SearchScreen, SettingsScreen, MiniPlayer, etc.)
      |
  [State & Presentation Layer]: PlayerViewModel, ExtensionsViewModel, StateFlow reactive bindings
      |
  [Domain / Business Layer]: MediaDataRepository, DesktopDownloadManager, DesktopLibraryManager
      |
  [Core Engine Layer]: VlcAudioPlayer (LibVLC binding), ExtensionManager (JAR ClassLoader isolate)
      |
  [Hardware & Platform Layer]: Windows OS Kernel, AWT EventQueue, JNA libvlc.dll / libvlccore.dll

4. CORE DATA MODELS & DOMAIN SCHEMAS
====================================================================================================
All media entities in Audix are strongly typed immutable data classes with serialization support.

4.1 Track:
  - id: String                       (Unique alphanumeric ID or foreign URI)
  - title: String                    (Song title, sanitized)
  - artists: List<Artist>            (List of contributing artists)
  - album: Album?                    (Parent album reference, nullable)
  - cover: ImageHolder?              (Artwork image holder: Network URL or local path)
  - duration: Long?                  (Duration in milliseconds)
  - plays: Long?                     (Play count or view count)
  - releaseDate: String?             (ISO date string or year)
  - explicit: Boolean?               (Explicit content advisory flag)
  - extras: Map<String, String>      (Routing dictionary: "extension_id", "local_file", "video_id", etc.)

4.2 Artist:
  - id: String                       (Artist identifier)
  - name: String                     (Artist display name)
  - cover: ImageHolder?              (Artist portrait image)
  - bio: String?                     (Biography text)
  - extras: Map<String, String>      (Additional metadata)

4.3 Album:
  - id: String                       (Album identifier)
  - title: String                    (Album display title)
  - artists: List<Artist>            (Album primary artists)
  - cover: ImageHolder?              (Album cover artwork)
  - trackCount: Int?                 (Number of songs in album)
  - releaseDate: String?             (Release date)
  - extras: Map<String, String>      (Additional metadata)

4.4 Streamable & Media:
  - Streamable.Media.Server:
    - id: String
    - sources: List<Streamable.Source.Http> (Ordered list of audio stream sources)
  - Streamable.Source.Http:
    - request: NetworkRequest (Target URL, User-Agent, Origin, Referer)
    - quality: Int (Bitrate in kbps: 320, 256, 160, 128)
    - title: String? (MIME type or codec label: "audio/mp4", "audio/webm", "Opus")

4.5 DownloadTask:
  - id: String (Track ID)
  - track: Track (Associated track metadata)
  - status: Status (QUEUED, CONNECTING, DOWNLOADING, COMPLETED, FAILED, CANCELLED)
  - progress: Float (0.0f to 1.0f)
  - bytesRead: Long (Downloaded byte count)
  - totalBytes: Long (Content-Length in bytes)
  - errorMessage: String? (Error description upon failure)

4.6 OfflineTrackMetadata (.echo.json sidecar file):
  - id: String
  - title: String
  - artists: List<String>
  - album: String?
  - coverUrl: String?
  - durationMs: Long?
  - format: String ("MP3", "M4A", "OPUS", "FLAC")
  - downloadTime: Long (Timestamp in milliseconds)
  - extensionId: String? (Persisted extension ID: "youtube_music", "saavn_music", "local_music", etc.)

5. AUDIO PLAYBACK ENGINE & PIPELINE SPECIFICATION
====================================================================================================
The playback engine is implemented in VlcAudioPlayer.kt, providing a native bridge to LibVLC.

5.1 Native LibVLC Discovery Hierarchy:
  When initialized, VlcAudioPlayer locates native binaries across the following prioritized paths:
  1. Bundled Application Runtime (Priority #1): <appBaseDir>\runtime\vlc\ (containing libvlc.dll, libvlccore.dll, plugins/)
     as well as relative directories relative to codeSource (<codeSourceDir>\runtime\vlc, ..\runtime\vlc).
     Guarantees the portable distribution always binds to the bundled 64-bit runtime rather than an incompatible or 32-bit system VLC.
  2. System Program Files: C:\Program Files\VideoLAN\VLC and C:\Program Files (x86)\VideoLAN\VLC
  3. Environment Variable: VLC_PLUGIN_PATH directory
  4. vlcj NativeDiscovery fallback scan

5.2 Native Tuning Arguments & Playback Flags:
  Audio streams are initiated with optimal low-latency flags:
  - :http-caching=400            (400ms network buffer to balance zero-stutter and fast seeks)
  - :network-caching=400         (400ms socket read buffer)
  - :live-caching=500            (500ms live stream buffer)
  - :http-reconnect=true         (Automatic reconnection on transient connection dropouts)
  - :clock-jitter=0              (Disables clock drift correction for real-time responsiveness)
  - :drop-late-frames=true       (Drops stale frames to prevent buffer accumulation)
  - :no-video                    (Completely disables video decoding pipelines to conserve CPU)
  - :audio-replay-gain-mode=none (Prevents artificial dynamic range compression)
  - MediaPlayerFactory Level Initialization: When audio_normalization is enabled, --audio-filter=normvol
    is registered directly at the MediaPlayerFactory constructor level, guaranteeing factory-wide volume
    leveling across all media without depending on per-media option parsing.

5.3 Playback State Machine:
  [IDLE] -> [LOADING] -> [BUFFERING] -> [PLAYING] -> [PAUSED] -> [ENDED]
    |           |              |            |            |          |
    +-----------+--------------+------------+------------+----------+---> [ERROR]
  - IDLE: No media loaded or stopped.
  - LOADING: Stream URL is being resolved by PlayerViewModel; audio component halted in 0ms.
  - BUFFERING: LibVLC cache pre-fill (< 100% buffer).
  - PLAYING: Active audio frame rendering. Position poller runs at 50ms interval for lyric sync.
  - PAUSED: Media paused; audio position held.
  - ENDED: Stream reached EOF. Triggers repeat logic (ONE -> replay, ALL -> skipNext, NONE -> skipNext if queue remains).
  - ERROR: Stream load failure. Triggers activeSources failover, or auto-recovery ceiling (max 3 retries).

5.4 Equalizer System:
  VlcAudioPlayer supports a 10-band graphic equalizer via vlcj's Equalizer API:
  - Frequencies: 60Hz, 170Hz, 310Hz, 600Hz, 1kHz, 3kHz, 6kHz, 12kHz, 14kHz, 16kHz
  - Preamp Gain: -20.0 dB to +20.0 dB
  - Band Gains: -20.0 dB to +20.0 dB per individual frequency band
  - Built-in Presets: Flat, Bass Boost, Vocal Enhancer, Rock, Pop, Jazz, Electronic, Classical

6. SEARCH & CANDIDATE RESOLUTION MATRIX (THE SEARCH-TO-PLAYBACK SPEC)
====================================================================================================
Audix implements a strict, multi-tiered resolution matrix to prevent audio desynchronization and
track hijacking.

6.1 Extension Attribution Pipeline:
  1. When a user clicks a song in the SearchScreen, SearchScreen automatically stamps
     track.extras["extension_id"] = currentExt.id.
  2. When PlayerViewModel.play(track) is called, it inspects the track origin in order:
     a. Explicit track.extras["extension_id"] if present.
     b. Local file indicator: if track.extras["local_file"] != null -> "local_music".
     c. 11-Character Alphanumeric ID regex (^[a-zA-Z0-9_-]{11}$) -> "youtube_music".
     d. 6-12 Digit Numeric ID regex (^\d{6,12}$) -> "saavn_music".
     e. Prefix "sc_" -> "soundcloud".
     f. URI containing "spotify:track:" -> "spotify_music".
     g. Active extension fallback from ExtensionManager.

6.2 YouTube Direct Resolution Priority (Zero Hijacking):
  In YoutubeExtension.kt:
  - Step 1: Direct YouTube Resolution (tryResolveYouTubeDirect)
    Connects to YouTube InnerTube API using the ANDROID_VR client (Quest 3 emulation).
    Directly extracts adaptive audio streams (Opus 160kbps, AAC 128kbps) from googlevideo.com.
    Requires NO signature cipher deciphering and plays the EXACT YouTube audio in under 200ms.
  - Step 2: Strict External Fallback (Only if Step 1 completely fails)
    Queries JioSaavn search API with target title and artist.
    Applies the Strict Candidate Scoring Algorithm (described below).

6.3 Strict Candidate Scoring Algorithm:
  Formula: Total Score = Title Score + Artist Score + Synergy Bonus - Noise Penalty
  - Minimum Qualification Threshold: Strictly 75 points (prevents title-only hijackings).
  - Title Scoring:
    * Exact Title Match: +60 points
    * Substring Title Match: +40 points
    * Word Overlap Ratio: up to +30 points
  - Artist Scoring & Hard Rejection:
    * Exact Artist Match: +35 points
    * Substring Artist Match: +25 points
    * Word Overlap Ratio: up to +20 points
    * ARTIST MISMATCH & COLLABORATION / SOUNDTRACK DURATION SYNERGY RULE:
      If target artist is known, candidate artist is known, and they share ZERO word overlap:
      - Default: SCORE = 0 (HARD REJECTION). This completely eliminates audio hijacking
        where songs with common titles (e.g., "Stay" by The Kid LAROI) were matched to unrelated
        songs by different artists (e.g., "Stay" by Jeet Gannguli).
      - Collaboration / Regional Soundtrack Fallback: If Normalized Title is an Exact Match (+60)
        AND track duration matches within ±3000ms (accounting for regional credits, e.g. YouTube
        crediting playback singer "Arijit Singh" vs. JioSaavn crediting composer "Pritam" on "Kesariya"),
        a Duration + Exact Title Synergy Bonus of +15 points is awarded (Total = 60 + 15 = 75 points).
        This allows genuine soundtrack / collaborator matches to reach exactly the 75-point threshold
        while hard-rejecting mismatched durations or title-only collisions (< 75).
  - Token Normalization:
    Strips noise tokens prior to comparison: "official", "video", "audio", "remastered", "lyric",
    "lyrics", "hq", "hd", "visualizer", "topic", "vevo".

9. DOWNLOAD ENGINE & OFFLINE METADATA SUBSYSTEM
====================================================================================================
Audix includes a robust offline download manager implemented in DesktopDownloadManager.kt.

9.1 Download Pipeline:
  1. Trigger: User clicks download icon on track, album, or playlist.
  2. Stream Resolution: Resolves exact audio stream URL via PlayerViewModel.resolveStreamUrl(track).
  3. SSRF Validation: Validates URL and all redirect hops against private/loopback address filters.
  4. Temporary File: Writes incoming audio chunks to <downloadDir>/<safeTitle>.part.
  5. Progress Throttling: Progress updates emitted at 250ms intervals to prevent UI thread thrashing.
  6. Atomic Rename: Moves <safeTitle>.part to final container (<safeTitle>.mp3 or <safeTitle>.m4a).
  7. Sidecar Metadata: Writes complete track metadata to <safeTitle>.<format>.echo.json.

9.2 Safe Filename Sanitization:
  - Replaces illegal filesystem characters (\ / : * ? " < > | \r \n \t) with underscores.
  - Windows Reserved Word Guard: If filename base matches CON, PRN, AUX, NUL, COM1-9, or LPT1-9,
    a leading underscore is prepended to prevent Windows kernel filesystem errors.
  - Hash Suffix: Appends a deterministic 6-character hex hash based on track ID to prevent collisions.

10. FULL-STACK SECURITY ARCHITECTURE & VULNERABILITY AUDIT LOG
====================================================================================================
A full-stack security audit was performed across the codebase. Below is the comprehensive audit log:

10.1 Vulnerability Log & Security Patches:
  - VULN-01 (SSRF Protection Bypass via HTTP Redirects):
    * Severity: HIGH
    * Vulnerable File: DesktopDownloadManager.kt
    * Issue: validateStreamUrl checked only the initial URL. A malicious stream URL redirecting to
      127.0.0.1 or 169.254.169.254 could access internal services.
    * Patch: Implemented an OkHttp NetworkInterceptor that inspects and validates the resolved IP
      address of EVERY HTTP redirect hop, rejecting loopback, link-local, and RFC 1918 addresses.
  - VULN-02 (Path Traversal in Extension Downloader):
    * Severity: HIGH
    * Vulnerable File: ExtensionsScreen.kt
    * Issue: Remote extension filenames were written without sanitization, risking directory traversal.
    * Patch: Enforced regex sanitization ^[a-zA-Z0-9._-]+$ and verified that
      targetFile.canonicalPath starts with destDir.canonicalPath.
  - VULN-03 (Data Race in Download State Manager):
    * Severity: HIGH
    * Vulnerable File: DesktopDownloadManager.kt
    * Issue: Concurrent coroutines mutated _activeDownloads list without synchronization.
    * Patch: Enforced atomic StateFlow .update { } functional transformations.
  - VULN-04 (Native LibVLC Deadlock on Callback Threads):
    * Severity: CRITICAL
    * Vulnerable File: VlcAudioPlayer.kt
    * Issue: Synchronous invocation of VLC controls inside VLC native event callbacks caused deadlocks.
    * Patch: Offloaded all player state modifications from event listeners to scope.launch(Dispatchers.IO).
  - VULN-05 (Screensaver Lockout Loop):
    * Severity: CRITICAL
    * Vulnerable File: EchoDesktopApp.kt
    * Issue: mouseExitedAt was not reset to 0L upon dismissal, causing immediate re-lockout.
    * Patch: Reset mouseExitedAt = 0L upon any screensaver dismissal, keypress, or mouse movement.
  - VULN-06 (Single-Instance IPC Token Storage & Socket Buffer Bounding):
    * Severity: HIGH
    * Vulnerable File: Main.kt
    * Issue: session.token was created without owner-restricted permissions, and the local IPC socket
      read lines without an upper boundary, risking local token interception or memory flooding.
    * Patch: Enforced owner-only file permissions (setReadable/setWritable) and bounded IPC socket reads
      to a maximum buffer of 512 characters with constant-time MessageDigest.isEqual token verification.
  - VULN-07 (Unmanaged JVM Threads in Settings UI):
    * Severity: MEDIUM
    * Vulnerable File: SearchAndOthers.kt
    * Issue: Cache clearing in the filtered search settings card spawned raw Thread { }.start()
      bypassing coroutine lifecycle scopes and prematurely displaying success dialogs.
    * Patch: Converted to structured coroutineScope.launch(Dispatchers.IO) with loading state tracking
      and main dispatcher completion notification.
